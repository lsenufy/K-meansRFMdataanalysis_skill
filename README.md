# K-meansRFMdataanalysis

**通用 RFM 与 K-means 用户分层工作流，以及可独立运行的 Python 计算助手。**

从实际数据探索出发，确定业务口径、评分规则和聚类方案，完成用户分层、基准比较与联合运营分析。适用于具有客户标识、时间、有效行为频次和价值信息的交易明细、订单记录及客户汇总数据。

## 完整流程

| 阶段 | 工作内容 |
|---|---|
| 数据治理与窗口设计 | 识别粒度、有效行为、退款与重复；构建客户级指标；按目标选择当前快照或时间外验证 |
| 规则型 RFM | 必须参考Shopify完整分组规则，根据数据选择评分阈值与适配标签，并检查覆盖与互斥 |
| K-means | 选择特征处理与候选K，结合肘部法、轮廓系数、跨随机种子ARI及业务画像确定最终方案 |
| 基准对比与优势评估 | 对照简单排序与随机参考，按相同客户范围和资源规模评价结果 |
| 交叉分析与业务落地 | 分析两套标签对应关系、联合客群差异，形成可追踪的运营矩阵 |

**时间切分可选。** 只有用户已约定且数据适用的未来窗口才开展时间外结果比较；当前结构任务完成结构、集中度、稳定性和运营可解释性比较，文件含较晚记录也不自动扩展。规则、标签数量、K值和窗口由每份数据重新确定，事后Oracle解读按约定交付。

**Agent独立判断，skill提供方法与检验。** 已授权范围内自主盘点、探索和比较；发现值得补充的工作或需要改变已约定方案时，先向用户说明依据、影响与建议并取得确认，已批准工作无需重复询问。

**确认后的合理探索独立保存，最终至少三轮自检。** 在`exploration/<topic>/`目录记录问题、授权、参数与结果；提升为主方案也需确认。最终依次核查数据、方法、结果与交付，保存证据，修复失败后复查。

## 两种使用方式

### 1. 作为 AI 分析技能／工作流

读取 [SKILL.md](SKILL.md)，由能够访问数据和运行代码的助手按需读取 `references/`，探索数据并推进完整流程。支持自动完成、逐步教学及续做已有分析。

在 Codex 中，将本文件夹放入技能目录并保持名称 `k-means-rfm-dataanalysis`。技能目录为 `$CODEX_HOME/skills`，默认 `~/.codex/skills`。调用示例：

```text
使用 $k-means-rfm-dataanalysis 分析我的订单数据。
请先探索数据，完成治理、规则型RFM、K-means、基准比较、交叉分析与运营建议。
本次只分析当前结构，不划分未来窗口。
```

其他环境也可直接使用 `SKILL.md` 作为工作流说明，并独立运行 Python 脚本。

### 2. 独立运行 Python 计算助手

需要 **Python 3.11+**。在仓库根目录安装依赖：

```bash
python -m pip install -r scripts/requirements.txt
```

运行纯合成客户示例：

```bash
python scripts/run_segmentation.py --config examples/config.json --output outputs/demo
```

输出目录必须尚不存在；再次运行时使用新目录，例如 `outputs/demo_02`。

示例使用三档评分与 K=3，仅用于演示接口和计算产物。示例数据为完全合成的数值，无真实客户、币种或业务收益含义。自己的数据应重新探索和选择规则、K 值。

五档Shopify分组示例：

```bash
python scripts/run_segmentation.py --config examples/shopify.config.json --output outputs/shopify_demo
```

Shopify参考采用`FM=floor((F+M)/2)`；只有已购客户时使用10类，有完整未成交名册时可单列Prospects。采用其他分组时说明与参考的关系。完整规则表见[评分与分群设计](references/rfm-rules.md)。

**脚本负责可复现计算，完整工作流还包括业务定义、最终方案选择、命名、结果解释和运营矩阵。** 这些工作由使用技能的助手或分析人员结合实际业务完成。

## 使用自己的数据

1. 探索字段含义与记录粒度，确定客户、订单／行为单元、有效行为、日期和价值口径。
2. 从 `assets/transactions.example.json` 或 `assets/customers.example.json` 复制配置到任务目录。
3. 修改输入路径、字段映射、评分、聚类、基准与可选未来窗口。相对输入路径以配置文件所在目录为基准。
4. 初次可以省略 `kmeans.k`，查看候选诊断与原单位画像后选择最终 K，在新输出目录完成最终版。
5. 完成基准行动排序、交叉解释和业务落地，不将候选输出当作最终成果。
6. 在独立目录开展需要的合理探索，确定最终版本后进行至少三轮自检，再交付结论。

配置详情见 [数据治理与计算配置](references/data-and-runner.md)。交易输入支持 CSV、XLSX、XLSM；客户级输入可直接提供 R/F/M。复杂订单生命周期、多个指标观察窗口和价值代理可先通过适配代码整理，再继续同一流程。

交易模式的amount表示支付／退款发生额。M若使用毛利或其他价值代理，应先独立按真实成交状态计算客户R/F/M，再用客户模式；负毛利不等于退款或未成交，不能依其正负删除订单。

## 至少三轮自检

生成示例结果后运行：

```bash
python scripts/self_check.py --run outputs/demo --output verification/demo_v1 --claims examples/numeric_claims.example.json
```

三轮分别核验数据与对账、方法与规则、结果与报告数字；每轮保存JSON证据，并生成汇总说明。示例声明的24客户、30645合成价值、120次行为只用于合成示例，自有数据必须替换为报告中的真实声明。

`pass`表示对应核对通过，`fail`需要修复，`review`需要语义或业务复核。用`review_resolutions.md`保存具体证据与判断，不能删除失败记录或仅口头改成通过；分析结果变化后使用新目录重新完成三轮检查。自动对账不证明外部来源真实性或运营因果收益。

完整协议见[合理探索与自检系统](references/exploration-and-self-check.md)。其他SQL／Notebook实现也应执行等价三轮核验，不限于该脚本格式。

## 主要计算能力

- R/F/M 分别选择分位数或原单位阈值，评分档数可配；支持通用矩阵、自定义规则及显式选用的平台模板。
- 支持零金额策略、合法负净值保留、历史 R 与近期窗口 F=0 的客户，以及明确的跨日订单日期口径。
- 支持按分布选择变换、StandardScaler／RobustScaler；每个候选K计算惯性、轮廓系数及跨种子ARI，输出肘部／轮廓／ARI三联图与原单位画像。
- 基准支持 M／F／R 排序、固定种子随机参考、RFM／Cluster 预先固定的行动优先级和等人数预算情景。
- 输出交叉人数、行／列占比与联合画像；可选冻结客户的未来及月度结果。

金额、行为次数、目标方向及分母必须保持一致。当前 M 排序在同一窗口上的金额覆盖是机械上界；交叉一致性也不等于独立验证。比较可得出基准更好、持平或分层带来额外行动信息等不同结论，具体以数据为准。

## 输出与文件结构

常见输出包括客户标签、规则人群与簇画像、K 诊断、基准排序／比较、交叉汇总及 `audit.json`。启用未来窗口时增加未来和月度结果；实际文件取决于配置。

最终应按[五阶段交付与结论规范](references/deliverables.md)提供业务结论。ARI判断比较协议下的稳定性，与肘部、轮廓和客群画像综合使用，不单独宣布普遍唯一最优K。

## 修复后的验证范围（2026-10-12）

- 通用示例、字面ID `NA`／`NULL`／`00123`、Shopify未来／月度案例均完成三轮自检，没有未解决的计算失败。
- 修改评价窗口／预算属性／机械上界／解释标识、污染结构人数／金额、删行或增加结构行的故障副本均被检测为失败。
- 35个错误布尔配置被明确拒绝，14个合法布尔配置及原有8项交易案例通过回归；毛利按真实完成订单先聚合客户RFM后，负毛利订单和客户正确保留。
- 独立复核再次验证ID和故障拦截。数值缺失与无意义份额仍保留缺失，不被错误改为0。

这是已验证场景的结果，不是对任意输入或所有业务结论的绝对保证。人工选K理由、来源语义、预算／因果解释等仍如实保留`review`，需要证据复核，不能改称全自动通过。
